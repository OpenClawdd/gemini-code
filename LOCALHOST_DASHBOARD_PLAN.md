# Localhost Dashboard Feasibility & Plan (v1.1)

## 1. Goal

Provide a read-only, glassy web mirror of the Gemini CLI Cockpit state, enabling
developers to monitor agent activity without tabbing back to the terminal.

## 2. Current Blockers (Forge Mode Audit)

- **Monorepo Type Hurdles:** Introducing CLI commands that depend on core-linked
  reactive states (like `AutopilotEvent`) frequently triggers
  `@typescript-eslint/no-unsafe-assignment` during pre-commit hooks. This is due
  to inconsistencies in how `dist` folders and `tsc` aliases are resolved across
  packages.
- **Service Registration:** The `BuiltinCommandLoader` in `packages/cli`
  requires strict type alignment with `SlashCommand` and `Config` from
  `@google/gemini-cli-core`. Small mismatches in dependency versions or build
  order cause hard-to-debug lint failures.
- **Port Safety:** Need a robust way to ensure the dashboard only binds to
  `127.0.0.1` and doesn't conflict with other local services.

## 3. Recommended Implementation Roadmap (Safe Path)

### Phase A: Type Alignment (The Foundation)

- Formalize the `AutopilotEvent` and `CockpitState` schemas in a shared types
  file that both Core and CLI can safely import without circularity or lint
  warnings.
- Fix `BuiltinCommandLoader` to use a more resilient registration pattern (e.g.,
  a registry service rather than an ever-growing array in a single file).

### Phase B: Read-Only Mirror (v0)

- **Server:** Use Node.js built-in `http` module only. No `express` or other
  external dependencies.
- **Security:** Strict binding to `127.0.0.1`. No command execution or
  file-serving endpoints.
- **Data:** A single `/state` JSON endpoint returning a combined snapshot of
  Cockpit, Buddy, and Event History.

### Phase C: UI Mirror

- Single HTML file with embedded CSS and Vanilla JS.
- Poll the `/state` endpoint every 2 seconds.
- Visuals: Dark mode, glassy cards, simple status indicators (green/yellow/red
  for gate decisions).

## 4. Why Implement This?

The dashboard moves the Cockpit from a "UI overlay" to a "data stream." It
allows for audit-ability and provides a foundation for more advanced
visualizations (like dependency graphs or multi-agent timelines) that are too
dense for a terminal screen.
